# NoSBP solo — упрощённый сервис генерации QR-кодов

Временная замена полному сервису: одна организация, только GET-запросы,
ни базы данных, ни объектного хранилища. Один контейнер и один файл
настроек — разворачивается на сервере, где уже работает сайт компании.

Картинка получается **побайтово той же**, что у полного сервиса:
платёжное ядро — строка ГОСТ Р 56042-2014 и отрисовка кода — берётся
из основного пакета, а не переписывается заново. За этим следит тест
`tests/test_solo.py`.

## Чего здесь нет

| Есть в полном сервисе | В упрощённом |
|---|---|
| Несколько заказчиков и организаций | Одна организация из `.env` |
| Тарификация, баланс, счета | Нет — ничего не считается |
| Личный кабинет, панель управления | Нет |
| PostgreSQL, S3, письма | Нет |
| `POST /v1/qr` с ключом в заголовке | Только `GET` |
| Логотип из хранилища | Логотип файлом с диска |

Адрес эндпоинта, имена параметров и заголовки ответа — те же. В шаблонах
CRM меняется **только адрес сервера**, и меняется обратно при возвращении.

## Что понадобится

- доступ по SSH к серверу, где стоит сайт, с правами `sudo`;
- домен сайта (или поддомен, если пойдёте вторым путём);
- реквизиты организации: наименование, ИНН, КПП, расчётный счёт,
  банк, БИК, корреспондентский счёт.

Порт наружу не открывается, поэтому в брандмауэре ничего менять не нужно.

## 1. Docker на сервере

Проверьте, есть ли он:

```bash
docker --version && docker compose version
```

Если команды не нашлись — поставьте:

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
```

## 2. Код на сервер

```bash
sudo mkdir -p /opt/nosbp-solo
sudo chown "$USER" /opt/nosbp-solo
git clone https://github.com/ВАШ_АККАУНТ/no-sbp.git /opt/nosbp-solo
cd /opt/nosbp-solo
```

Если репозитория на GitHub ещё нет, скопируйте каталог проекта
со своей машины:

```bash
rsync -av --exclude .git --exclude .venv ./ user@server:/opt/nosbp-solo/
```

## 3. Настройки

```bash
cd /opt/nosbp-solo
cp solo/.env.example solo/.env
chmod 600 solo/.env
```

Сгенерируйте ключ доступа и сразу запишите его — он понадобится
в шаблоне CRM:

```bash
openssl rand -base64 32
```

Откройте `solo/.env` и заполните:

```bash
nano solo/.env
```

| Переменная | Что вписать |
|---|---|
| `QR_TOKEN` | Ключ из команды выше |
| `PAYEE_NAME` | Наименование получателя, как в банке |
| `PAYEE_INN` | ИНН: 10 цифр у ООО, 12 у ИП |
| `PAYEE_KPP` | КПП, 9 цифр. У ИП КПП нет — оставьте пустым |
| `PAYEE_ACCOUNT` | Расчётный счёт, 20 цифр |
| `PAYEE_BANK_NAME` | Название банка |
| `PAYEE_BIC` | БИК банка, 9 цифр |
| `PAYEE_CORR_ACCOUNT` | Корреспондентский счёт банка, 20 цифр |
| `ORG_ALIAS` | Значение `org` из ваших шаблонов CRM. Обычно `main` |

Реквизиты проверяются при старте: у счетов и ИНН считаются контрольные
разряды. **Опечатка не даст контейнеру подняться** — это намеренно.
Сервис, работающий с неверным счётом, хуже не работающего: клиент
оплатит в никуда, и узнаете вы об этом нескоро.

Логотип в центре кода — необязательно:

```bash
cp ~/logo.png /opt/nosbp-solo/solo/logo/logo.png
# и в solo/.env раскомментировать:
# LOGO_PATH=/app/logo/logo.png
```

## 4. Запуск

```bash
cd /opt/nosbp-solo
docker compose -f docker-compose.solo.yml up -d --build
```

Сборка занимает пару минут. Проверьте, что сервис жив:

```bash
curl -s http://127.0.0.1:8081/health
# {"status":"ok"}
```

Проверьте, что картинка рисуется (подставьте свой `QR_TOKEN`):

```bash
curl -s -o /tmp/proverka.png \
  "http://127.0.0.1:8081/v1/qr?token=ВАШ_КЛЮЧ&sum=100000&purpose=Проверка"
file /tmp/proverka.png
# /tmp/proverka.png: PNG image data, 690 x 690, 1-bit grayscale

# Размер зависит от длины реквизитов и назначения платежа —
# важно, что это PNG, а не страница с ошибкой.
```

Скачайте файл к себе и отсканируйте телефоном — в приложении банка
должны подставиться ваши реквизиты и сумма 1000 ₽.

```bash
scp user@server:/tmp/proverka.png ~/Downloads/
```

Если контейнер не поднялся, посмотрите причину:

```bash
docker compose -f docker-compose.solo.yml logs qr
```

Ошибка в настройках выглядит так — сервис называет переменную и что
с ней не так:

```
Сервис не запущен. Реквизиты получателя: Контрольный разряд счёта не сходится…
```

## 5. nginx

Два пути. Первый проще: ничего не ждём, новый сертификат не нужен.

### Вариант А: путь на существующем сайте (рекомендуется)

Адрес получится `https://example.com/qr?token=…`.

Сначала найдите конфиг вашего сайта:

```bash
sudo nginx -T | grep -n "server_name\|root" | head -20
ls -la /etc/nginx/sites-enabled/
```

Возьмите два блока из [`solo/nginx/location.conf`](nginx/location.conf):

1. Строку `limit_req_zone …` вставьте в `http`-секцию — обычно это
   `/etc/nginx/nginx.conf`, рядом с другими такими же строками.
2. Блоки `location = /qr` и `location = /qr-health` вставьте внутрь
   `server`-блока вашего сайта, того, что слушает 443.

Примените:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

> Если сайтом управляет панель (ISPmanager, FastPanel, cPanel), правьте
> конфиг через её раздел «дополнительные директивы nginx» — иначе панель
> перезапишет файл при следующем изменении настроек сайта.

### Вариант Б: отдельный поддомен

Адрес получится `https://qr.example.com/v1/qr?token=…`.
Потребуется A-запись в DNS и свой сертификат.

```bash
# 1. В панели управления доменом добавьте A-запись qr → IP сервера,
#    дождитесь, пока она разойдётся:
dig +short qr.example.com

# 2. Конфиг
sudo cp /opt/nosbp-solo/solo/nginx/subdomain.conf \
        /etc/nginx/sites-available/nosbp-solo.conf
sudo sed -i 's/qr\.example\.com/qr.ВАШ-ДОМЕН/g' \
        /etc/nginx/sites-available/nosbp-solo.conf
sudo ln -s /etc/nginx/sites-available/nosbp-solo.conf /etc/nginx/sites-enabled/

# 3. Сертификат
sudo certbot --nginx -d qr.ВАШ-ДОМЕН

sudo nginx -t && sudo systemctl reload nginx
```

## 6. Проверка снаружи и шаблон CRM

Со своей машины, не с сервера:

```bash
curl -s -o ~/Downloads/proverka.png \
  "https://example.com/qr?token=ВАШ_КЛЮЧ&sum=4700000&purpose=Заказ+1234"
open ~/Downloads/proverka.png
```

Теперь в шаблоне письма или счёта в CRM поменяйте адрес картинки.

Было:

```html
<img src="https://nosbp.ru/v1/qr?token=КЛЮЧ&sum={{ сумма_в_копейках }}&purpose=Заказ+{{ номер }}"
     alt="QR-код для оплаты">
```

Стало (вариант А):

```html
<img src="https://example.com/qr?token=КЛЮЧ&sum={{ сумма_в_копейках }}&purpose=Заказ+{{ номер }}"
     alt="QR-код для оплаты">
```

Сумма передаётся **в копейках**: 47 000 ₽ — это `4700000`.

Отправьте себе тестовое письмо из CRM и проверьте, что код сканируется.

## Эксплуатация

```bash
cd /opt/nosbp-solo

# Журнал
docker compose -f docker-compose.solo.yml logs -f qr

# После правки solo/.env — перезапуск, пересборка не нужна
docker compose -f docker-compose.solo.yml up -d

# После обновления кода
git pull
docker compose -f docker-compose.solo.yml up -d --build

# Остановить
docker compose -f docker-compose.solo.yml down
```

Ключ доступа в журнал не пишется. Сумма и назначение платежа — пишутся.

## Возвращение на основной сервер

Когда новый сервер заработает:

1. Поднимите на нём полный сервис по основному
   [README](../README.md#развёртывание).
2. Верните в шаблонах CRM прежний адрес картинки.
3. Убедитесь, что новые письма приходят с рабочим кодом.
4. Остановите упрощённый сервис и уберите блоки из nginx:

```bash
cd /opt/nosbp-solo
docker compose -f docker-compose.solo.yml down
docker image rm nosbp-solo
```

Спешить с шагом 4 не нужно: упрощённый сервис ничего не стоит,
пока стоит. Пусть повисит неделю как запасной путь.

## Если что-то не работает

| Что видно | В чём дело |
|---|---|
| Контейнер висит в состоянии `restarting` | Ошибка в `solo/.env`. Сообщение в журнале называет переменную и что с ней не так |
| `curl` на 8081 не отвечает | Контейнер не поднялся: `docker compose -f docker-compose.solo.yml ps` |
| Порт 8081 занят | Поменяйте его в `docker-compose.solo.yml` и в конфиге nginx |
| В письме картинка с текстом «Ключ не найден» | `token` в шаблоне не совпал с `QR_TOKEN` |
| Картинка с текстом «Организация не найдена» | `org` в шаблоне не совпал с `ORG_ALIAS` |
| Картинка с текстом «Неверные параметры» | Чаще всего `sum` не число: проверьте подстановку в CRM |
| 404 от nginx на `/qr` | Блок `location` попал не в тот `server`-блок |
| 502 от nginx | Контейнер лежит либо слушает другой порт |
| Код сканируется, но реквизиты чужие | Проверьте `PAYEE_*` в `solo/.env` |

Ошибки сервис намеренно отдаёт **картинкой с читаемым текстом**, а не
кодом ответа: адрес стоит в теге `<img>` уже отправленного письма,
и код ответа превратился бы у получателя в битую иконку. Машиночитаемый
код дублируется в заголовке `X-NoSBP-Error`, а `on_error=status`
переключает поведение на обычный JSON.
