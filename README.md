# NoSBP

Сервис отдаёт QR-код для оплаты **по банковским реквизитам** (ГОСТ Р 56042-2014)
обычной ссылкой на картинку. Плательщик сканирует код банковским приложением,
деньги приходят переводом на расчётный счёт — без эквайринга и без его комиссии.

Взамен деньги приходят не мгновенно, а на следующий рабочий день. Это
осознанный размен: комиссия 0,7 % с чека в 47 000 ₽ — это 329 ₽ с заказа,
здесь тот же заказ стоит 1 ₽.

## Как это выглядит у заказчика

Одна строка в шаблоне письма или счёта:

```html
<img src="https://nosbp.ru/v1/qr?token=ВАШ_КЛЮЧ&sum=4700000&purpose=Заказ+1234"
     alt="QR-код для оплаты">
```

Ключ передаётся в адресе картинки намеренно: шаблонизаторы CRM (RetailCRM,
МойСклад и другие) умеют вставлять только адрес и не умеют ни заголовков,
ни POST-запросов. Чем это ограничено — см. «Модель доступа» ниже.

Для интеграций, которые умеют делать настоящие запросы, есть `POST /v1/qr`
с ключом в заголовке `Authorization`.

## Тарификация

Заказчик платит **за счёт, а не за обращение к API**.

Счёт — это уникальный набор параметров: организация, сумма, назначение
платежа, данные плательщика. Первое обращение с новым набором создаёт счёт
и списывает 1 ₽. Любое повторное обращение с теми же параметрами в течение
30 дней бесплатно.

Так сделано потому, что картинка живёт в письме: получатель открывает его
несколько раз, пересылает бухгалтеру, почтовый клиент делает предзагрузку,
антивирус проверяет ссылку. На 60 отправленных счетов приходится 200–400
обращений. При тарификации за обращение заказчик увидел бы в выписке
списание втрое больше ожидаемого.

Сама картинка нигде не хранится: повторный запрос приносит те же параметры,
поэтому QR рисуется заново. Это дешевле, чем держать десятки тысяч файлов
в сутки и потом их вычищать.

**Овердрафт.** Когда баланс кончился, сервис продолжает работать в долг
без ограничения по сумме — кассовый разрыв у заказчика не должен
останавливать его продажи. Овердрафт можно продлить.

Все числа выше — стоимость счёта, длительность бесплатного периода,
срок и число продлений овердрафта, минимальное пополнение — задаются
переменными окружения. Полный список с умолчаниями лежит
в `.env.example`, определения — в `src/nosbp/core/config.py`.

## Персональные данные

ФИО и телефон плательщика попадают в QR-код, но **в базу не сохраняются**.
Они участвуют только в вычислении ключа идемпотентности, то есть превращаются
в необратимый хэш SHA-256. Восстановить из него фамилию нельзя.

Хранение персональных данных плательщиков остаётся заботой заказчика.

## Запуск для разработки

Нужны Docker и Poetry.

```bash
cp .env.example .env
docker compose up -d postgres minio
poetry install --with dev
poetry run alembic upgrade head
poetry run uvicorn nosbp.main:app --reload
```

Документация API — http://localhost:8000/docs

### Тесты

Тесты работают против настоящего PostgreSQL: корректность списаний держится
на блокировке строки `SELECT ... FOR UPDATE`, которой в SQLite нет.

```bash
docker compose up -d postgres
createdb_cmd="CREATE DATABASE nosbp_test OWNER nosbp"
docker exec nosbp-postgres psql -U nosbp -d postgres -c "$createdb_cmd"
poetry run pytest
```

Отдельная группа тестов читает выданный QR-код обратно программным
сканером — с логотипом, цветом и длинной кириллической строкой. Ещё одна
проверяет, что стоимость счёта, сроки овердрафта и остальные числа
действительно берутся из настроек, а не зашиты в код.

### Проверки перед коммитом

```bash
poetry run ruff check . && poetry run ruff format --check . && poetry run mypy && poetry run pytest
```

## Заведение заказчика

Пока нет личного кабинета, всё делается консольной утилитой.

```bash
# 1. Учётная запись
poetry run nosbp account create --email shop@example.com --name "ООО Ромашка"

# 2. Организация-получатель. Реквизиты проверяются по контрольным разрядам:
#    опечатка в счёте не пройдёт.
poetry run nosbp org add \
  --email shop@example.com \
  --alias main --name "ООО Ромашка" \
  --account 40702810000000000007 \
  --bank "ПАО Сбербанк" --bic 044525225 \
  --corr 30101810000000000007 \
  --inn 7707083893 --kpp 773601001 \
  --color "#0e6b62" --logo ./logo.png --default

# 3. Ключ доступа. Показывается один раз.
poetry run nosbp token issue --email shop@example.com --label RetailCRM

# 4. Пополнение баланса
poetry run nosbp topup --email shop@example.com --rubles 1000

# Выписка
poetry run nosbp balance --email shop@example.com
```

## Модель доступа

Ключ виден в адресе картинки — значит, его увидит и получатель письма.
Риск обсуждён и принят: украсть деньги по ключу нельзя, реквизиты получателя
зашиты в аккаунт и в запросе не передаются. Единственное, что даёт утечка, —
возможность выжечь баланс генерацией счетов с разными параметрами.

Что этому противостоит:

* **суточный потолок списаний** — по умолчанию 500 ₽ для новых аккаунтов,
  снимается флагом `--daily-limit 0`;
* **мгновенный отзыв ключа** — `nosbp token revoke --prefix XXXXXXXX`;
* **несколько ключей на аккаунт** — по одному на интеграцию, чтобы отзывать
  точечно, не ломая остальные;
* в базе лежит только SHA-256 от ключа: из дампа рабочий токен не достать.

## Ошибки

QR-код живёт в теге `<img>` уже отправленного письма. Если ответить кодом 402,
получатель увидит битую иконку и не поймёт, что делать.

Поэтому `GET /v1/qr` по умолчанию отдаёт ошибку **картинкой с текстом**, а
машиночитаемый код кладёт в заголовок `X-NoSBP-Error`. Параметр
`on_error=status` переключает на обычные коды ответа и JSON.

## Структура

```
src/nosbp/
  core/        настройки, логирование, доменные ошибки
  db/          модели и подключение к базе
  storage/     объектное хранилище логотипов (S3 и заглушка в памяти)
  payments/    ГОСТ-строка, отрисовка QR, проверка реквизитов, HTTP-эндпоинты
  billing/     баланс, списания, овердрафт, журнал операций
  invoices/    поиск или создание счёта — оркестрация горячего пути
  scripts/     консольная утилита администрирования
alembic/       миграции схемы
tests/         тесты, работают против настоящего PostgreSQL
```

## Развёртывание

```bash
docker compose -f docker-compose.prod.yml up -d
```

Миграции накатываются при старте контейнера. Отключается переменной
`RUN_MIGRATIONS=0`, если миграции делаются отдельным шагом деплоя.

Наружу сервис слушает только `127.0.0.1:8000` — перед ним должен стоять
обратный прокси, который терминирует HTTPS.
